# Sentinel 回滚缺陷：`git checkout --` 会销毁未暂存工作

> 级别：🔴 **P0（数据丢失）**｜发现日期：2026-09-10｜状态：**✅ 已修复并实测验证**（v3.0 基线恢复）
> 实证来源：`data/logs/self-sentinel-error.log`（harness-self-sentinel）
>
> **修复摘要**：新增 `sentinel/baseline.cjs`（「最后授权内容」快照）→ `rollback.cjs` 回滚改为
> **从基线恢复**（`git checkout` 路径整体删除）→ `sentinel-service.cjs` 启动播种基线 +
> 授权分支刷新基线 + 无基线时 fail-loud。详见下方「六、修复实施」。

## 一、现象

维护会话中对 `src/types.ts` 的一次合法编辑（当时无有效豁免）触发 self-sentinel 拦截并回滚。
回滚后文件**并非**回到「编辑前状态」，而是回到 **git index（暂存区）版本** —— 该文件此前
**全部未暂存的 enhance-v1 改动被一并抹除**（`confirmations_pending` / `s3_patch_loop` /
`unresolved_confirmations` / `full_review_evidence` / `run_signals` / `superseded` 等类型扩展），
导致 `tsc --noEmit` 出现 **21 处编译错误**（构建中断），需人工逐项重建。

日志实证：
```
2026-09-10 11:44:45: [sentinel] 📁 文件变更: src/types.ts (#7)
2026-09-10 11:44:45: [sentinel] 🚫 拦截: src/types.ts — 中高风险文件 "src/types.ts" 无有效令牌
2026-09-10 11:44:47: [sentinel] ❌ 回滚失败: src/types.ts — git checkout 后文件仍有变更
2026-09-10 11:44:47: [sentinel] 📁 文件变更: src/types.ts (#8)
2026-09-10 11:44:49: [sentinel] ❌ 回滚失败: src/types.ts — git checkout 后文件仍有变更
```

## 二、根因

`sentinel/rollback.cjs:101`：

```js
execSync(`git checkout -- "${filePath}"`, { cwd: projectRoot, ... });
```

`git checkout -- <file>` 的语义是「用 **index（暂存区）** 覆盖工作区」，**不是**「撤销本次编辑」。
因此：

1. **销毁未暂存改动**：文件在 index 之上累积的、尚未 `git add` 的改动全部丢失。
   index 与工作区的差距越大，损失越大——本项目 index 明显落后于工作区（大量 staged 与
   unstaged 并存），命中概率高。
2. **回滚不完整且自相矛盾**：若文件本身有**已暂存**改动，`git checkout --` 之后
   `git status --porcelain` 仍返回 `M `（首列 M）→ 校验分支判为「回滚失败」→
   重试 → 最终 `❌ 回滚失败`，同时 breaker 计数被无效消耗。这正是上面日志中
   「git checkout 后文件仍有变更」的成因。
3. **untracked 文件直接删除**（`rollback.cjs:111-123`）：新文件被删而非告警。

## 三、影响面

- 任何在 `WATCH_ROOTS`（`src/` `.claude/` `mcp/` `sentinel/` `scripts/` `hooks/` `data/flows/`）下、
  且**工作区领先 index** 的受管文件，在被拦截回滚时会丢失未暂存工作。
- 对 harness 自身（self-sentinel）与 wenstar-cc（sentinel）同样成立。
- 属**静默数据丢失**：用户只看到「回滚」，不知道丢了什么。

## 四、修复方向（原始建议 —— 实际实施以 §六 为准）

> 本节为发现当日提出的候选方向；最终采用的方案见 §六，与本节第 1/3/5 条一致，
> 第 2 条（继续用 git）未采纳，第 4 条扩展为「隔离后可删」。

1. **改为快照回滚**：在「文件变更」事件触发时（或拦截判定前）先把当前内容快照到
   `data/sentinel/snapshots/<hash>/<ts>`；回滚 = 恢复该快照，而非 `git checkout`。
2. **若坚持用 git**：至少改为 `git checkout HEAD -- <file>` 之外的三方恢复，
   并在动手前 `git diff -- <file>` 备份到快照目录；**禁止**在文件存在未暂存改动时无备份回滚。
3. **回滚判据修正**：校验「是否与快照一致」而非 `git status --porcelain` 是否为空
   （后者对 staged 文件恒为真 → 永远判失败）。
4. **untracked 文件**：默认只告警 + 快照，不直接 `unlinkSync`。
5. **失败必须响**：`回滚失败` 应升级为告警事件（当前仅写 stderr 一行），避免静默。

## 五、规避（当前可用的运维手段）

- 对受管文件做任何编辑前，先取**有效豁免**（`harness-cli.cjs exempt add`）。
  实证：豁免命中时 self-sentinel 走 `exempt_allowed` 分支**不回滚**
  （`2026-09-10 11:50:45: [sentinel] 🟡 豁免内修改(无令牌): src/types.ts — id: ex-3c8e2e31 豁免期内不回滚`）。
- 或先取得该文件的流水线令牌（`harness_run_flow`，令牌有效 → 直接放行）。
- 编辑前把文件当前内容另行落盘备份（最稳，与 Harness 机制无关）。

## 六、修复实施（v3.0 —— 2026-09-10 当日完成并实测）

### 变更清单
| 文件 | 变更 |
|---|---|
| `sentinel/baseline.cjs`（**新增**） | 「最后授权内容」基线：`refresh` / `restore` / `seedDirs` / `has` / `currentHash`。存储 `data/sentinel/baseline/<项目指纹>/{index.json, files/}`（**不在** WATCH_ROOTS 内 → 不自激） |
| `sentinel/rollback.cjs`（**v3.0**） | `git checkout` 回滚路径**整体删除**；改为基线恢复；新增 `quarantine()`（破坏性动作前强制隔离）与 `isTrackedByGit()`；校验判据改为「恢复后内容哈希 == 基线哈希」 |
| `sentinel/sentinel-service.cjs` | 启动全量播种基线（`seedDirs(WATCH_ROOTS)`，只补缺失不覆盖）；分支 1/2（令牌/豁免 = 授权）→ `baseline.refresh`；分支 3 → 识别幂等 `noop` 与 `refused-no-baseline`（告警升级） |
| `tests/sentinel/baseline.test.ts`（新增，8 用例） | 基线模块单测（含「事故复现」用例与跨进程持久化） |
| `tests/sentinel/rollback-baseline.test.ts`（新增，5 用例） | 回滚语义集成测试（含**回归护栏**：源码不得再出现 `execSync('git checkout`） |

### 新语义（三分支）
1. **令牌有效 / 豁免命中**（授权）→ 放行，并**推进基线**（此后回滚精确恢复到本次授权态）。
2. **无授权 + 有基线** → **基线恢复**：精确撤销本次改动，不触碰该文件其它任何工作。
   恢复动作自身会重写文件 → 再触发一次事件 → 命中幂等分支 `noop`（不打日志、不升级），收敛。
3. **无授权 + 无基线** → **绝不破坏**：先隔离当前内容，untracked 新文件隔离后删除（可找回）；
   git 已跟踪文件 **拒绝回滚 + fail-loud 告警**（`refused-no-baseline`）。

### 实测验证（live，2026-09-10 14:01）
对事故原文件 `src/types.ts` 做同样的**无豁免编辑**：

```
14:01:40 [sentinel] 📁 文件变更: src/types.ts (#1)
14:01:40 [sentinel] 🚫 拦截: src/types.ts — 中高风险文件 "src/types.ts" 无有效令牌
14:01:40 [sentinel:rollback] ↩ 已按基线恢复: src/types.ts (基线 dd2c0ad96f7e)
14:01:41 [sentinel] 📁 文件变更: src/types.ts (#2)      ← 幂等收敛，无 #3/#4 风暴
```
- 编辑后哈希 `dd2c0ad96f7e6700` **与编辑前逐字节一致** → **内容零丢失**（事故不再复现）
- 审计：`data/sentinel/2026-09-10/reverted_*.json`（基线哈希）+ `noop_*.json`（「内容已与基线一致」）
- 播种：`🧬 基线播种完成: 新增 151 / 已有 0 / 失败 0（8 个根目录）`
- 回归：`tsc --noEmit` 0 错误；`vitest run` **610/610 通过**（35 文件）

### 运维含义（重要变化）
- **不再有「静默销毁」**：任何回滚都可从基线/隔离区找回。
- 基线在**启动时**播种。哨兵重启后，重启瞬间的磁盘状态即被视为「已知状态」——
  若在哨兵停机期间发生了未授权改动，重启后不会被回滚（无历史基线）。这是有意的取舍。
- `refused-no-baseline` 告警表示「哨兵无法自动回滚」：需人工确认改动合法性后，
  取豁免/令牌重写以推进基线，或从 `data/sentinel/quarantine/<时间戳>/` 比对处理。
