### 它是不是 Agent？—— 不是

- 无自主目标设定、无自驱任务生成：只**被动响应** `run_flow` 调用，决策者始终是外部 agent
- "智能"成分 = 确定性评分校验 + S4/S4.5 的 LLM 评审，非自主决策
- 学习回路**开着**；安全防线**是真的**
- 最贴切类比：**监管/合规 + 审计 + 执行系统**，而非 agent

跨到 agent-grade 缺三样：**闭环学习（自动应用规则且可回滚）**、**目标分解**、**自发起修复**。

### P0-2 真实 live run 验证
- **问题**：S6-B / S7-B 的单元与集成测试已覆盖各分支，但**真实 S1→S7 全流程未跑过**。

  1. S6-B 未确认 → 是否**悬挂终局** `run_status=await_manual_verification`（且不签发 token）

## 三、P2｜中期：信号质量（当前噪音大于信号）

### P2-1 误报治理
- **`cluster_attack` 误判**：EvolutionEngine 把**合法的多文件 agent 编辑**判为
  `severity: critical` 的「批量修改攻击」。实证：本次 harness 维护期间被记 10 条。
  → 需引入「已授权批次」白名单（同一 flow 的多文件改动不应等于攻击）。
- **`totalSentinelErrors: 5168` 偏高**（对比 reverts 833 / allowed 1946）→ 需归因
  （疑似历史「回滚失败」风暴累积，Sentinel v3.0 已消除该来源，应观察其收敛趋势）。

### P2-2 收敛速度
- **`avgConvergenceRounds = 5.7`**，而 L1 目标 ≤2.5、L2 门槛 3 —— **差一倍以上**。
- 排查方向：① S4.5 打分是否过严；② 驳回理由是否「不可执行」（导致 S3 空转）；
  ③ 23 条标准的权重分配是否偏斜。
