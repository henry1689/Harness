## 2. 各 S 阶段审计（目标 / 实现 / 缺口 / 契约对齐 / 迁移联动）

### S1 问题收录 + 影响盘点（local / auto / 只读）
- **目标**：复述目标、风险分级、import 牵连清单、核心耦合点探测、FG 红线判定、DB 影响。
- **实现**：stage 只读（tool_whitelist read/search/run_cli_check，write/delete 关）；`CK-00`(checkGlobalSurvey) 出 import 牵连 + 耦合点 + FG 红线触碰表；CK-06.5 全仓同类扫描（S1 亦触发，见 stage 10）。
- **缺口**：
  - 高风险文件名单（chat.ts/FamilyGraph.ts/…）在 YAML **硬编码**，与引擎 DS-06/09/流程多处重复维护——单点漂移债。
  - "只读锁死"依赖 tool_whitelist 软约束；S1 work_manual 含"禁止写文件"措辞，但无独立校验 write 计数。
  - FG 红线表要求 Read `wenstar-fg-roleplay.md`——是 prompt 指令非强制 Read 审计。
- **契约对齐**：铁律 1/6/10 部分由 CK-00 自动覆盖，其余靠 prompt。
- **迁移联动**：S1 的 import 牵连 + 大文件 touch 概率是 P0-P3「大文件拆分(#8)」的天然触发雷达。

### S2 方案定稿（local / human / 唯一人工终审）
- **目标**：共性/个性归类 + 全局优化提案二选一 + 分步清单 + 验证/回滚方案 + 存入 memo。
- **实现**：human gate（approval_ref 等 s2_evidence 必填，缺失→fail-closed）；`inject_global_memo`；`CLASSIFY_FALSE_SPECIFIC` 事后防"共性伪装个性"。
- **缺口**：
  - "归类二选一/优化提案"是 prompt 文本要求，**非机器校验**；机器只在 S4 用文本特征反查归类真实性（`[归类·拦截]`），覆盖不全。
  - confirmations 需与 reviewer 的 key **精确匹配**；Agent 无法预知 reviewer 将要求哪些 key（P0-A2 已把"不知道"的代价从 20 轮降到 1 次提前终局，但首轮仍需探测）。
- **契约对齐**：方案合规性校验(prompt) vs 10 铁律冲突自动检测缺失——靠 S4/S4.5 事后。
- **迁移联动**：优化提案弹性(规则9)与知识库 growth A/B/C 的"上升空间"理念同源；P0/P1 债务项在此声明进入当轮范围。

### S3 代码落地（local / condition / 白名单）
- **目标**：增量 diff 精确修改，禁整文件重写；S4/S5/S6 驳回回流。
- **实现**：condition gate + `conditionGateCheck`（S3 tsc 前置自检）；P0-A2 S3 回流熔断(retry_limit)；work_manual 强制 Edit 非 Write、逐轮只修驳回项。
- **缺口（高）**：
  - **配置自相矛盾**：YAML S3 work_manual 写"驳回最多 3 轮"，flow 顶层 `max_s3_retries:20`——实证 run_mts7hzf2/run_mtrksrpx 烧满 20 轮才锁。文案与配置不一致直接放大返工成本。
  - diff 模式是 **prompt 软约束**：YAML 给 S3 开了 `write_file:true`，引擎无"禁止整文件 Write"硬闸。
  - S3 回流每轮由 Agent 重跑，"修什么"依赖 S4/S4.5 驳回清单是否完整回流上下文（见 §5 上下文注入缺口）。
- **契约对齐**：save()/scheduleFlush、FG 主/分支隔离、_meetingEntityName 12 处同步在 S3 自检清单(prompt) + CK-05/06(机器) 双轨。
- **迁移联动**：大文件拆分期间 S3 是"拆一块验一块"的主战场；Write 硬闸缺失在拆分时风险最高。

### S4 架构评审（delegate / auto）
- **目标**：CK-01~07 本地硬校验 + 11 维语义评审 + 共性/个性真实性。
- **实现**：delegate 进程内 `DelegateReviewer.review`：11 维(Arch/FG-UUID/Coupling/Persist/Risk/Doc/Classify/Static/Robust/Hook/Proposal)，H1 结构化 `review_details{blocking, confirmations_missing/met, advisories}`；`uuid_chain_broken` rule 级硬判。
- **缺口**：
  - 文本化 blocking 曾致 P0-A 死锁——已重构为结构化 + 义务分流（见 P0-A）。
  - `REVIEW_INVARIANT` fail-closed 检查严格，结构性要求高（11 维齐全）。
- **契约对齐**：铁律 6(MEETING_PROP_POINTS 编目 grep 核验) 在此强审。
- **迁移联动**：S4 的 CLASSIFY 反伪装是 P0 债务整改"只修问题不顺手优化"的护栏。

### S4.5 收敛闸门（delegate / condition）
- **目标**：CK-00~11 重跑 + 11 维违规 → 23 设计标准逐条打分 ≥98 才放行；收敛趋势。
- **实现**：`ConvergenceGate.evaluate` + `ComplianceScorer`；P0-A(义务/簿记不计文本分) + B(CK-06.5 名称碰撞→warn) + P0-A2(确认阻塞提前终局) 当日修复全在。
- **缺口（高）**：
  - **引擎-项目耦合债**：23 条 DS 中 DS-02/05/06/08/09/23 等是 wenstar-chat **全文件契约**硬编码进"通用"引擎 ComplianceScorer/DesignStandards——部分补丁结构性不可过 → P0-B(契约-里程碑 overlay) 方向已定"先重跑实测"。
  - 文字 warn(-15) 对 DS 仍有拖累；B 后 CK-06.5 不再硬拒但候选清单需 Agent 判读（人性化负担）。
- **契约对齐**：23 DS 实质是 10 铁律的评分投影；契约与 DS 映射隐式（靠命名），无显式契约清单。
- **迁移联动**：P2#8 大文件拆分必须在拆分完成里程碑一次性通过 DS-02/06/09——这正是 P0-B 的触发场景。

### S5 编译测试（local / condition）
- **目标**：补丁嗅探(CK-08) + tsc + vitest 全量 + 模块专项。
- **实现**：runCommand 本地；CK-08 单函数 ≥2 if 分支标记"疑似补丁"。
- **缺口**：补丁嗅探阈值启发式（无法区分真加固/规避——由 LLM 逐条评定，软约束）。
- **契约对齐**：静态质量(规则5第一层)硬落地。
- **迁移联动**：P0 铁律(空 catch/as any)由 tsc/noImplicitAny 部分承接，非全部。

### S6 功能验证（local / condition）
- **目标**：tsc+vitest 复跑 + CK-09 回归 + CK-10 意图达成 + save() 落盘 grep +（原规范）三场景行为测试 + DB 审计。
- **缺口（高）**：YAML 自注"原 S6 规范保留，供 LLM 参考"——**WebUI 三场景(对话/会晤/角色扮演)、DB 标注率、停服重启**标注为参考而非必跑；实际只跑脚本层。行为级验证依赖外部 Agent 手动，流水线自身不闭环行为验证。
- **契约对齐**：铁律 3/5/8(数据只增不删/save 落盘/Hook) 由 CK-06/09 部分覆盖；角色隔离行为验证缺机器闭环。
- **迁移联动**：P0 复审三段式(停服→重启→查库)在此被降级为"参考"——与 CLAUDE.md 复审铁律有落差。

### S7 变更归档（local / auto）
- **目标**：汇总 + 写变更台账 + 回滚/验证清单 + 修复总结 + 大重构三轮复审提示。
- **实现**：local Agent 自写归档到审计卷宗。
- **缺口（高）**：**归档无独立校验**（无 delegate/无清单机器核验"是否真归档、台账是否更新"）；负债台账联动缺失（见 §5）；三轮复审是 prompt 提示非闸门。
- **迁移联动**：P0-P3 债务清零的"验收+稳定2天"状态无自动化跟踪。

## 5. 漏洞标注（用户点题四类）

### 5.1 易滑向补丁思维的环节
1. **S3 回流上限配置与文案冲突(20 vs 3)** → 补丁被反复驳回时 Agent 倾向"打一个 if 绕过"，20 轮内无结构性纠偏信号。**建议**：max_s3_retries 与文案统一；回流≥3 轮且分平/升时强制提示"回到 S1/S2 重审方案"而非继续 S3。
2. **S3 write_file:true + diff 软约束**：整文件重写无法被硬闸拦截（CK-09 回归安全仅事后）。
3. **CK-08 补丁嗅探阈值启发式** + CK-06.5 名称碰撞(已降 warn)：机器提示→人判，判读负担下沉给 Agent。
4. **S4 CLASSIFY 反伪装是文本特征**：Agent 换措辞可绕过（无规则级归类校验）。

### 5.2 缺全局架构约束的位置
1. 10 铁律/9 规则以 **prompt 文本**注入，无结构化契约模型；DS 与铁律映射隐式。
2. **DS 标准 = wenstar 特定契约硬编码进"通用"引擎**（DesignStandards.ts/ComplianceScorer）——引擎与项目契约耦合，且**无契约基线/里程碑机制**（P0-B；部分补丁结构性不可过）。
3. 顶层架构（白皮书/蓝皮书分层）与流水线无**自动化比对**——仅 CK-01~05 覆盖九层/FG/UUID/会晤片段。

### 5.3 负债台账联动缺口
1. S7 归档自写无独立校验；**无自动负债台账**记录每 run 的 S4.5 分/回流轮数/补丁标记（数据在 audit 卷宗，未聚合为债务趋势）。
2. wenstar-cc CLAUDE.md P0-P3 债务项（空 catch/as any/大文件拆分/process.env…）**无机器跟踪状态**；EvolutionEngine 30 条规则建议堆在 pendingUpgrades 无审核入口。
3. P2#8 大文件拆分与 P0-B 契约里程碑应共享一份债务台账，现各自独立。

### 5.4 下游编码上下文注入完整性
1. S2 后 memo 注入 ✅；S4/S4.5 结果以 reject_reason 回流 ✅（P0-A 后=可行动清单）。
2. **截断风险**：S4.5 的 DS 差距/11 维明细大量落在 audit JSON 文件，回流给 Agent 的仅 reject_reason(前 8) + 报告摘要——**全量评审证据未必进编码上下文**，Agent 可能"只见结论不知依据"而盲目改。
